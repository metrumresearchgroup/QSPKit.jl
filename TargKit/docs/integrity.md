# Data Integrity

TargKit provides SHA-256 hash verification for data source files, ensuring that target values derived from data files are reproducible and that data file changes are detected.

## Overview

When targets load values from CSV files via `from_data()`, those files can change over time (corrections, new data, format changes). TargKit's integrity system:

1. **Generates** a lockfile containing SHA-256 hashes of all referenced data files
2. **Verifies** hashes at load time, warning if files have changed
3. **Integrates** with TracKit for reproducible experiment tracking

## lock_hashes!()

Generate or update a lockfile:

```julia
lock_hashes!(targets_file; lockfile=nothing)
```

### Arguments

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `targets_file` | `String` | (required) | Path to the Julia file containing `from_data(...)` calls |
| `lockfile` | `String` or `nothing` | `nothing` | Output lockfile path (defaults to same name with `.lock` extension) |

### How it works

1. Reads `targets_file` as text
2. Finds all `from_data("...")` calls via regex
3. Resolves file paths relative to the directory containing `targets_file`
4. Computes SHA-256 for each referenced file
5. Writes hashes to the lockfile

### Example

```julia
using TargKit

# Generate lockfile
lock_hashes!("model/targets.jl")
# Creates model/targets.lock
```

### Lockfile format

```
# TargKit data integrity lockfile
# Generated by lock_hashes!() -- do not edit manually
data/clinical_baseline.csv = a1b2c3d4e5f6...
data/gadkar_fig4.csv = f6e5d4c3b2a1...
```

Plain text, sorted by path, one `path = hash` per line. Lines starting with `#` are comments.

## Automatic Verification

When TargKit loads a `DataSource` (via `observe(data)` in `@target`), it automatically:

1. Looks for a `.lock` file near the data file (same directory or parent)
2. If found, checks the file's SHA-256 against the stored hash
3. **Warns** on mismatch (does NOT error -- verification is advisory)
4. Silently passes on match
5. If no lockfile is found, prints an `@info` message once per session

### Warning example

```
WARNING: Data file hash mismatch! Target values may have changed.
  path = data/clinical.csv
  expected = a1b2c3d4...
  actual   = 9f8e7d6c...
```

## verify_hashes()

Manually verify a collection of sources:

```julia
results = verify_hashes(sources::Vector{<:Source}; lockfile=nothing)
```

Returns a vector of NamedTuples:

```julia
[(path="data/file.csv", expected="a1b2...", actual="a1b2...", match=true), ...]
```

### Example

```julia
# Collect all sources from a TargetSet
sources = [t.source for t in ts if !isnothing(t.source)]
results = verify_hashes(sources)

for r in results
    if !r.match
        println("MISMATCH: $(r.path)")
    end
end
```

## Workflow

### Initial setup

```julia
# 1. Define targets with from_data sources
# model/targets.jl:
baseline = @targetset :baseline begin
    @target eos begin
        source = from_data("data/clinical.csv", filter=(visit="baseline",))
        observe(data) = Observed(mean(data.eos_count); range=(1.5, 4.0))
    end
end

# 2. Generate lockfile
using TargKit
lock_hashes!("model/targets.jl")
# Writes model/targets.lock

# 3. Commit both targets.jl and targets.lock to version control
```

### After data updates

```julia
# 1. Update the data file
# 2. Re-run to see the warning:
#    WARNING: Data file hash mismatch!
# 3. Verify the change is intentional
# 4. Regenerate the lockfile:
lock_hashes!("model/targets.jl")
# 5. Commit the updated lockfile
```

### Integration with TracKit

When using TracKit's `run_experiment()`, the lockfile verification runs automatically as part of the experiment setup, ensuring that recorded results correspond to verified data files.

## fingerprint()

Generate a deterministic hash of one or more `TargetSet`s:

```julia
fingerprint(target_sets::TargetSet...)::String
```

Returns a 16-character hex string (truncated SHA-256) computed from target names, values, ranges, weights, loss types, and sorted metadata. The fingerprint changes whenever any target definition changes.

### Use with TracKit

Pass the fingerprint to TracKit's config dict so cached results are automatically invalidated when targets change:

```julia
config = Dict(
    "model_name" => "MU2_DrugResponse",
    "target_fingerprint" => fingerprint(baseline, drug_response),
)

run_experiment(config, model_fn) do prob, sys, cfg
    # ...
end
```

DrWatson-based caching in TracKit uses the full config dict as the filename key, so a changed fingerprint triggers a fresh run.

## Design Decisions

- **Advisory, not blocking:** Hash mismatches produce warnings, not errors. This avoids blocking development when data is actively being updated.
- **Separate lockfile:** Hashes are stored in a lockfile (not inline in the source) to keep target definitions clean and to allow regeneration without modifying source code.
- **Regex-based scanning:** `lock_hashes!()` scans for `from_data("...")` patterns via regex rather than executing the file. This is fast and doesn't require loading the full target definition.
- **Relative paths:** File paths in the lockfile are relative to the targets file directory, making lockfiles portable across machines.
