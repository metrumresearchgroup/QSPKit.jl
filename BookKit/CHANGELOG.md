# Changelog

All notable changes to BookKit.jl will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed
- **`fit_quality` folded into `metrics`**: `book!`'s `fit_quality` is now also recorded in the open `metrics` table (deprecated in favor of `metrics`); the legacy `fit_quality` column is still written for back-compat.
- **Artifact `.data` is consistent across `book!`/`lookup`**: `book!("fig", artifact(...))` now returns the file bytes as `.data` (matching `lookup`), not the `Artifact` wrapper.
- **`book!` truncates its own internal file reads on EVERY exit (incl. exceptions)**: the `FILE_READS` cleanup is now in a `try/finally`, so an error mid-`book!` (e.g. a missing artifact) can no longer leak `book!`'s own Manifest/blob reads into a later, unrelated booking's attribution (a false-positive staleness source).
- **Environment capture resolves versioned/explicit Manifest names**: `_manifest_path` now prefers `Manifest-v$(major).$(minor).toml` (and the `JuliaManifest*` forms) over the plain `Manifest.toml`, matching how Julia/Pkg selects the manifest — so env capture isn't silently skipped on projects using a versioned manifest.
- **`book_extract(::BayesResult)` strips the live `log_density` before storing**: the booked payload is now `strip_log_density(r)`, avoiding a bloated, cross-session-unrestorable JLD2 blob (the live runtime holds closures/state JLD2 can't portably serialize) and stabilizing the result hash.
- **`restore` no longer clobbers an out-of-root artifact's original file**: a snapshot path can be absolute (an artifact booked from outside the store root), and `joinpath(to, abspath)` discards `to` and overwrites the original. Absolute snapshot paths are now relocated under `to`.
- **Re-booking with changed `loss`/`metrics` is recorded, not silently skipped**: the duplicate-booking skip now includes metrics (and the folded `loss`) in its identity test, so re-scoring a result with a new objective records a new revision instead of keeping the stale loss/metrics.
- **`loss=` and `metrics["loss"]` can no longer diverge**: when both are supplied, the explicit `loss` kwarg is authoritative and overwrites `metrics["loss"]` (with a warning), so the queryable column and the metrics table always agree.
- **An artifact file is snapshotted exactly once** (it was double-counted via `book!`'s own `blob_put_file!` read landing in `FILE_READS`).
- **A `book_extract` that omits `payload` now stores the original result** (was silently `nothing`), and `_load_blob` falls back to raw bytes when blob metadata is missing rather than mis-deserializing.
- **TargKit source fingerprinting can't destroy a completed fit**: the `combined_fingerprint` call in `fit()` is guarded — on failure it logs and falls back to `source_fp=nothing`.
- **`book!` no longer attributes written output files as input dependencies**: file attribution now consults the open mode recorded by StoreKit's file tracking (`StoreKit._is_read_mode`) and skips files opened for writing/appending. Previously a file the computation *wrote* during the run was snapshotted as a `"data"` dependency, so regenerating that output later produced a false-positive staleness warning from `lookup(...; verify=true)`. Read inputs are unaffected.
- **`book!` now attributes data files (not just `.jl` source)**: file attribution was filtered through StoreKit's `_is_user_file`, which is `.jl`-only (it drives IR source-dependency tracing), so attributed data files (`.csv`, `.txt`, …) were silently dropped and no file snapshots were recorded. `book!` now filters through the new `StoreKit._is_attributable_file` predicate (any project-local file that exists and is not a package/stdlib/StoreKit-internal/`.provenance` path).
- **`book!` now stores attributed file contents as blobs**: previously `book!` recorded each snapshot's `content_hash` but never wrote the file's bytes to the blob store, so `restore` failed with "Blob not found" once snapshots were actually produced. File bytes are now persisted via `StoreKit.blob_put_file!`, keyed by the file's raw SHA-256 so the snapshot hash both references the stored blob (for `restore`) and matches re-hashing the live file (for `lookup(...; verify=true)`).

### Added
- **`staleness_sweep(; stale_only=true)`**: A project-wide "what is stale now?" query — runs `staleness` over every booked result and returns the `(name, report)` pairs (stale ones by default).
- **`book_extract(::SimKit.PopulationResult)`**: Books a population simulation as a `:prediction`, fingerprinting the shared model/solver plus the per-subject params/doses across all subjects.
- **Numerical-environment fingerprints**: `capture_env` now also records `julia_threads`, `blas_threads`, `cpu`, and `os` (diff-at-rebook) — knobs that can change floating-point results via reduction order / platform.
- **`BookKitBayesKitExt` + RNG-seed capture**: With BayesKit loaded, `book_extract(::BayesKit.BayesResult)` books a posterior run, capturing the reproducibility seed (`BayesResult.rng_seed`) as an in-memory dependency fingerprint (under strict reproducibility, a reseed reads as a changed input) plus `n_chains`/`n_subjects`/`wall_time` metrics. BayesKit gained an `rng_seed` field on `BayesResult` (populated from `options.sampling.rng_seed` and threaded through persistence so it survives cold/reloaded `.bkr` results). (SimKit needs no seed dimension — its simulation is deterministic.)
- **Environment capture (`capture_env=true`, default on)**: `book!` now records the package environment automatically — the active `Manifest.toml` as a cold-verifiable file dependency (the files dimension flags a dependency/version change on the next verify) and the Julia `VERSION` (plus a Manifest content hash) as diff-at-rebook fingerprints (a Julia/env change forces a new booking). Pass `capture_env=false` to skip. `book!`'s own internal file reads (result/artifact/Manifest blobbing) no longer pollute attribution.
- **`artifact(path)` — book a file (figure/CSV/report) as the result**: `book!("gof", artifact("figs/gof.png"))` stores the file's raw bytes as the result blob and records it as an on-disk dependency the staleness check cold-verifies (editing the file flags the booking stale). Routes around the fragile `Base.open` attribution for outputs you want to book explicitly; `lookup` reads it back as bytes and `restore` round-trips it. Result-blob loading now picks `blob_get` vs `blob_get_file` by the stored blob type.
- **`BookKitSimKitExt` (weakdep extension)**: With SimKit and ModelingToolkit loaded, `book_extract(::SimKit.SimContext)` books a simulation as a `:prediction` with in-memory dependency fingerprints — the model (Route 3: a structural, order-independent hash of `equations(sys)`, since the MTK system is a RuntimeGeneratedFunction invisible to IR tracing), the solver config, the parameters, and the dosing events. So `book!("sim", sim_context)` captures the model/solver/params/doses fingerprints automatically.
- **`BookKitTargKitExt` (weakdep extension)**: With TargKit loaded, `book_extract(::TargKit.FitResult)` books a fit with zero ceremony — `:accepted`/`:rejected` from `converged`, metrics from `loss`/`report`, and dependency fingerprints for the parameters (bit-exact, order-independent) and the producing source code (`FitResult.source_fp`). So `book!("MU3", fit_result)` captures params + code fingerprints automatically.
- **`book_extract(r)` + no-ceremony `book!(name, result)`**: A result type can describe how it should be booked — payload, status, metrics, and dependency fingerprints — via `book_extract(r)`; `book!(name, result)` then dispatches on the result's type to derive all of that automatically (explicit `status=` overrides the extracted hint, else a missing status errors loudly). The generic fallback books any object opaquely. `book!(name, status::Symbol; ...)` remains the explicit escape hatch (chosen by dispatch). Package extensions specialize `book_extract` for `FitResult`/`SimContext`.
- **Open `metrics` dict on `book!`**: `book!(...; metrics=Dict(...))` records advisory metrics (e.g. `"rmse"`); `loss` is folded in both directions so the queryable `loss` column and the metrics table agree. (`fit_quality` is unchanged for now.)
- **`book!(...; fingerprints=Dict())` + a fingerprints staleness dimension**: `book!` now accepts a `fingerprints::Dict{String,String}` of in-memory dependency hashes (e.g. `"params"`, `"model"`, `"solver"`, `"source"`), persisted per annotation. `StalenessReport` gains a 5th dimension, `fingerprints`, that compares a booking's fingerprints to the immediately-prior booking of the same name (diff-at-rebook — in-memory deps have nothing on disk to cold-re-hash): a shared key with a changed value is stale; added/removed keys are informational. The duplicate-booking skip is widened so a re-booking that changes only a fingerprint is still recorded. (Also normalized the duplicate-skip's `result_hash`/`rationale` comparison to fold SQLite `missing` so result-less re-bookings don't error.)
- **`staleness(name; recurse=true, revision=:latest) -> StalenessReport`**: Structured staleness check across four dimensions — **files** (attributed data files re-hashed vs their snapshots), **upstream** (consumed upstream results whose current content drifted from the hash pinned at booking time, walked transitively with cycle/visited guards), **vcs** (the recorded VCS ref vs the current working tree, git/svn-aware), and **blob** (the result blob re-hashed vs its content-addressed key). `StalenessReport`/`DimResult` carry per-dimension `checked`/`stale`/`details`; `is_stale(report)` gives the overall verdict. `revision` can target a past booking. This wires up provenance that was previously captured but never checked (`result_inputs.input_hash`, `vcs_ref`, the result blob). `lookup(...; verify=true)` now builds the same report and emits a single advisory warning when stale; a missing/corrupt result blob degrades to `data=nothing` under `verify=true` (and still fails loud on the default path). Phase 1b of `docs/staleness_redesign_plan.md`.
- **`lineage_graph(project; granularity=:unit)`**: Automatically discovers a project's compute/dependency DAG and returns it as a `LineageGraph`. Edges are the `latest(name=…)` / `lookup(…)` provenance reads in each modeling unit's run/plot scripts; nodes are the booked results, enriched with store metadata (timestamp, content hash) and classified as `:fit` (calibrated) vs `:prediction` (held-out). `granularity=:unit` (default) collapses `MU<k>_*` results into modeling-unit nodes (`MU1`, `MU2`, …) and drops intra-unit edges; `:result` keeps every booked result. Accepts a project root directory or a `StoreKit.Store` handle.
- **`to_dot(g)`**: Render a `LineageGraph` as a Graphviz `dot` string (fit nodes teal, prediction-only nodes amber).
- **`render_lineage(g, outpath)`**: Write the graph to `.dot`, or shell out to Graphviz (`dot`) for `.svg`/`.png`/`.pdf`.
- **`to_metagraph(g)`**: Convert to a `MetaGraphsNext.MetaGraph` carrying node/edge metadata (via a package extension loaded when `Graphs` + `MetaGraphsNext` are present).
- **`LineageGraph`, `LineageNode`, `LineageEdge` types** plus `nodes`, `edges`, `roots`, `leaves` accessors.
- **Dependency-edge recording**: `lookup` now records each upstream result it reads, and `book!` persists those reads (plus an explicit `inputs=` keyword, accepting `name => label` pairs) as `result_inputs` rows. This lets the provenance store itself encode the consumption DAG that `lineage_graph` recovers. `clear_consumption!()` discards pending reads.

## [0.1.0] - 2026-03-31

### Added
- **`book!(name, status; result, rationale, fit_quality, loss)`**: Core booking function that records a modeling decision with full provenance — result storage in the StoreKit blob store, file attribution via StoreKit session log, VCS state capture, and SQLite annotation.
- **`lookup(name; verify=false)`**: Retrieve the latest booked result by name. With `verify=true`, checks SHA-256 hashes of attributed files against stored snapshots and warns if any changed (staleness detection).
- **`history(name)`**: Display all bookings for a name as a formatted table showing status, timestamp, VCS ref, and loss.
- **`restore(name; to=path)`**: Extract file snapshots from a booking to a target directory, recreating the exact file state at booking time.
- **`BookedResult` type**: Wrapper struct with property forwarding — `result.fitted_params` transparently delegates to the wrapped data object.
- **Decision files**: Each `book!` call generates a human-readable Markdown summary at `.provenance/decisions/<slug>.md` containing rationale, fit quality, fitted parameters, scores, and attributed files.
- **VCS integration**: Captures git or svn state (ref + dirty flag) at booking time. Controlled by `ENV["BOOKKIT_VCS"]`.
- **File attribution**: Two modes — interactive (traces StoreKit SESSION_LOG dependency graph backward from result variable) and script (uses all tracked file reads).
- **Staleness detection**: `lookup(; verify=true)` compares current file hashes against stored snapshots, warning about changed or deleted files.
